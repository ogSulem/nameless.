# nameless. — анонимный чат-бот

Анонимные диалоги один-на-один, рейтинг собеседников, Premium-подбор и полноценная
панель модерации. Бот работает в России, поэтому в основе не только UX, но и
152-ФЗ/54-ФЗ: явное согласие, сроки хранения, удаление данных по запросу, чеки.

```
python 3.11 · aiogram 3.15 · SQLAlchemy 2 (asyncpg) · PostgreSQL 16 · Redis 7
```

---

## Что умеет

**Для пользователя**

| | |
|---|---|
| Анонимный поиск | очередь по городу + федеральный fallback, матч по полу и возрасту |
| Диалог 1-на-1 | текст, фото, видео, голосовые, кружки, стикеры, гифки — пересылаются копией, без «forwarded from» |
| Оценки | шкала 0–10 кнопками, два шага (общение / внешность), пропуск, «Пожаловаться» |
| Рейтинг | байесовское сглаживание: одна «нулёвка» не убивает новичка |
| Premium | приоритет на собеседников с рейтингом 7+, разовая оплата без автопродления |
| Управление | `/stop` в любой момент, «⏭️ Следующий», «🛑 Завершить», удаление профиля `/delete_me` |
| Юридическое | экран согласия перед регистрацией, `/privacy`, `/terms`, `/help`, `/delete_me` |

**Для команды**

| | |
|---|---|
| Роли | `SUPPORT` (чтение) → `MODERATOR` (баны/муты/жалобы) → `ADMIN` (платежи, Premium, журнал) |
| Панель | `/admin` в личке: статистика, карточка пользователя, очередь жалоб с перепиской, платежи, журнал действий, обслуживание |
| Аудит | каждое действие модерации — строка в `admin_audit`: кто, что, когда, над кем |
| Оповещения | ошибки и оплаты уходят в `ALERTS_CHAT_ID`, без текста переписки пользователей |

## Быстрый старт

```bash
cp .env.example .env        # заполните BOT_TOKEN, DB_*, REDIS_*, ADMINS
docker compose up -d --build
docker compose logs -f bot
```

Локально без Docker:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head        # нужен PostgreSQL
python -m app.main
```

Проверки:

```bash
pytest -q                   # 77 тестов, изоляция на SQLite + fakeredis
ruff check app tests
python -c "import app.main" # тот самый smoke-тест, который ловит битые wheels
```

## Архитектура

```
Telegram ──► middlewares ──► routers ──► handlers ──► services ──► Postgres / Redis
             │                                        │
             ├ Logging (correlation id, метрики)      ├ matchmaking  — очередь, матч, Premium
             ├ AppContext (settings, redis)           ├ dialog       — жизненный цикл, heartbeat
             ├ Dedupe (повторы update)                ├ rating       — байес, анти-накрутка
             ├ Presence (online, last_seen)           ├ payments     — лимиты, идемпотентность
             ├ ErrorBoundary (алерт без PII)          ├ yookassa     — шлюз, чеки, возвраты
             ├ DbSession (одна сессия на update)      ├ vision       — «есть ли лицо на фото»
             └ BanGate (бан в одной точке)            └ admin        — запросы панели + аудит
```

**Состояние диалога.** Источник истины — таблица `active_dialogs`, Redis держит только
кэш с TTL и heartbeat. Если Redis потерял ключ (деплой, eviction, 12 ч простоя),
следующее сообщение чинит кэш из БД — раньше такие пользователи зависали навсегда.

**Матчинг.** Кандидат забирается атомарным Lua-скриптом (`ZRANGEBYSCORE` + `ZREM`),
поэтому два одновременных поиска физически не могут взять одного человека. Отбракованный
кандидат возвращается в очередь с прежним приоритетом, а не теряется.

**Деньги.** Каждая попытка оплаты — строка `payments` с суммой, валютой и сроком.
`successful_payment` применяется ровно один раз (повторный вебхук/апдейт ничего не
удваивает), сумма сверяется, при расхождении статус `amount_mismatch` и алерт.

## Панель модерации

`/admin` в личке боту. Кнопка «Пользователь по ID» принимает и Telegram ID, и внутренний
`id`. Карточка показывает пол/возраст/город, рейтинг общения и внешности, число оценок,
Premium, бан/мут, сколько открытых жалоб, сколько диалогов и сколько человек заплатил.

| Действие | Роль | Пишется в журнал |
|---|---|---|
| посмотреть статистику/карточку/жалобы | support | — (просмотр жалобы — да) |
| бан / разбан / мут 1 ч | moderator | да |
| закрыть / отклонить жалобу | moderator | да |
| выдать Premium +30 дней, сбросить рейтинг | admin | да |
| платежи, журнал, обслуживание (retention) | admin | да |

Жалоба открывается вместе с последними сообщениями диалога — этого достаточно для
решения и не требует постоянного зеркалирования всех фото в админ-чат (старая схема).
Сообщения старше `RETENTION_MESSAGE_DAYS` к моменту разбора уже удалены: это ограничение
политики, оно написано и в `/privacy`.

Кто получает доступ:

```env
ADMINS=111111111            # полный доступ
MODERATORS=222222222        # баны, жалобы
SUPPORT=333333333           # только чтение
```

Пустой `ADMINS` + заполненный `ALERTS_CHAT_ID` = бот **не стартует** (защита от
случайно открытой панели).

## Юридическая часть

Бот помогает соблюдать требования, но не заменяет юриста. Чек-лист — в
[`docs/LEGAL.md`](docs/LEGAL.md).

- **Согласие.** Экран перед регистрацией: 18+, условия, политика. В БД пишется
  `consent_at` + `consent_version`, поэтому версия документов отслеживается.
- **Сроки хранения.** Сообщения и фото — 30 дней, жалобы — 180, журнал — 365
  (`RETENTION_*`). Чистка идёт автоматически (sweeper), вручную — кнопкой в панели.
- **Право на удаление.** `/delete_me` жёстко удаляет профиль, диалоги, сообщения, фото,
  оценки; запись об удалении остаётся в журнале, платёжные документы — на срок,
  установленный законом.
- **Чеки (54-ФЗ).** Telegram Payments получает `provider_data.receipt`; прямая ЮKassa —
  объект `receipt` с e-mail покупателя (бот спрашивает его до оплаты).
- **Автопродления нет.** Premium — разовая покупка на 30 дней, что прямо написано в оферте.
  Это снимает и риск возвратов «я не подписывался».

## Конфигурация

Все переменные — в [`.env.example`](.env.example) с комментариями. Самое важное:

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `DATABASE_URL` / `DB_*`, `REDIS_URL` / `REDIS_*` | хранилища |
| `ADMINS` / `MODERATORS` / `SUPPORT` | RBAC панели |
| `ALERTS_CHAT_ID` | куда слать ошибки и оплаты |
| `SUBSCRIPTION_PRICE_RUB`, `SUBSCRIPTION_DAYS` | цена и срок Premium |
| `PAYMENTS_PROVIDER_TOKEN` | Telegram Payments (чеки на стороне провайдера) |
| `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` | прямая ЮKassa + вебхук `/yookassa/webhook` |
| `RATING_*` | сглаживание рейтинга |
| `RETENTION_*` | сроки хранения |
| `OPERATOR_NAME`, `SUPPORT_CONTACT` | реквизиты в `/privacy` и `/help` |

## Структура

```
app/
  config.py          настройки (pydantic-settings, fail-fast)
  access.py          роли и проверки
  main.py            запуск: polling, singleton-lock, health, sweeper
  handlers/          команды, поиск, диалог, оценки, платежи, админка, fallback
  middlewares/       logging, app_context, dedupe, presence, error_boundary, db, gates
  services/          matchmaking, dialog, rating, payments, yookassa, admin, vision…
  keyboards/         инлайн-клавиатуры
  database/          модели и Alembic-миграции
tests/               pytest + fakeredis + aiosqlite + фейковый Telegram
docs/                аудит и юридический чек-лист
```

## Эксплуатация

- `/healthz` — процесс жив; `/readyz` — реально проверяет Postgres и Redis (503 при сбое).
- Singleton-lock в Redis: второй экземпляр не начнёт polling, а выйдет с кодом 1.
- Метрики (обновления/ошибки/медленные хендлеры) пишутся в лог раз в минуту.
- Миграции идут под `pg_advisory_lock`, поэтому параллельный деплой не ломает схему.
